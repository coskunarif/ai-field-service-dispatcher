## Vault orientation
$ vault --help
vault — workspace knowledge gateway

Don't guess. Don't use memory. Ask vault first.
Per-command help: vault help <command>

── ORIENT ──────────────────────────────────────────────────────────────
  vault orient                        # one-word bootstrap (= read workspace-map --compact)
  vault orient --meta                 # metadata only — triage without consuming context
  vault read file="workspace-map"     # equivalent, explicit form

── RETRIEVE ────────────────────────────────────────────────────────────
  read file="name"               read known truth directly; refuses ambiguity    [free]
  search query=".." [--limit N]  discover files/tools (default 5 compact, 12)    [free]
    [--type T] [--since H]       filter by type (prefix/plural ok) and/or recency
  search-deep query=".."         cross-file reasoning (~25s, ~$0.008)            [api]

── INVENTORY ───────────────────────────────────────────────────────────
  list [--compact] [--brief]     searchable inventory: skills, knowledge, scripts, projects [free]
  recent [N] [--since H]         N most recently changed files (default 20)       [free]
  diff [--compact]               what changed since last catalog build             [free]

── WRITE BACK ──────────────────────────────────────────────────────────
  append file="name" entry=".."  file a discovery (deterministic local write, --dry-run) [free]

── INSPECT ─────────────────────────────────────────────────────────────
  stats [--compact]              counts, freshness, health summary                [free]
  health [--compact]             structural health check (9 checks)               [free]
  profile [--compact]            index size breakdown by type                     [free]

── MAINTAIN ────────────────────────────────────────────────────────────
  lint [--compact] [--file X]    content health — contradictions, gaps            [api]
  sweep [--compact] [--file X]   decay review — stale, superseded entries         [api]
  catalog [--check] [--compact]  rebuild skill catalog (auto-heals drift)         [free]
  index [--compact]              force-rebuild retrieval index                    [free]
  selftest [--compact]           smoke test all commands                          [free]
  bench [--compact]              retrieval precision benchmark (file-backed, 60-120s) [free]

── UTILITY ─────────────────────────────────────────────────────────────
  version [--compact]            version, paths, dirs, benchmark
  help [command]                 per-command help with examples

── ALIASES ─────────────────────────────────────────────────────────────
  s/find/grep/lookup → search       r/get/show/open/cat → read
  sd/deep/reason → search-deep      a/add/write/log → append
  ls/dir/all → list              latest/new/modified → recent
  status/info → stats            check/validate → lint
  clean/decay/stale → sweep      test/smoke → selftest
  h/-h/--help → help             -V/--version → version

── AGENT OUTPUT (--compact / --json) ───────────────────────────────────
  Every command supports --compact (or --json) for machine-readable JSON.
  Envelope: ok, command, _vault, _schema, _ts, _cost, _latency_ms on every response.
  _schema: integer — increments on breaking output changes. Current: 1.
  _cost: "free" or "api" — check before calling api-backed commands.
  _latency_ms: actual wall-clock time for the command.
  _alias: present only when an alias was used (e.g., "s" → search).
  _index_rebuilt: true when index was rebuilt during this call (explains latency spikes).
  Errors: ok=false + error.type + error.message + error.recoverable.
  search --limit N controls result count (default 5 in --compact, 12 human).
  search --type T filters by source type (knowledge, skill, script, doc=project docs + overlays).

## Audit Workflow

### `/seo audit [url]`

Run these in parallel, then synthesize into a unified 0–100 score:

**Phase 1 — Technical (25pts)**
```
- Fetch robots.txt → check AI crawler permissions
- Check sitemap.xml presence and validity
- Verify canonical tags in raw HTML (not JS-injected)
- Check HTTPS, redirect chains (max 1 hop)
- Mobile viewport meta tag
- Core Web Vitals proxy: page size, render-blocking resources
- llms.txt presence
```

**Phase 2 — On-Page (20pts)**
```
- Title tag: 50–60 chars, contains primary keyword, compelling
- Meta description: 140–160 chars, includes CTA
- H1: one only, matches search intent
- H2/H3: logical hierarchy, question-based where relevant
- URL: lowercase, hyphens, keyword-containing, max 60 chars
- Internal links: min 3 relevant, descriptive anchor text
- Image alt text: all images described
```

**Phase 3 — Content Quality / E-E-A-T (25pts)**
```
- Experience: first-hand data, original research, case studies
- Expertise: author credentials, depth, accuracy
- Authoritativeness: external citations, mentions
- Trustworthiness: About page, contact, privacy, HTTPS
- Freshness: publication + last-updated dates present
- Depth: covers topic comprehensively vs thin content
```

**Phase 4 — GEO Readiness (15pts)**
```
- Direct answer in first 60 words?
- Definition blocks using "X is..." pattern?
- Statistics with sources cited?
- Self-contained 134–167 word blocks?
- FAQ section present?
- Author bio present?
- Schema present (FAQPage, Article, SoftwareApplication)?
```

**Phase 5 — Schema (10pts)**
```
- JSON-LD present (not Microdata/RDFa)
- Types valid for 2026: Organization, SoftwareApplication, FAQPage, Article, Review
- No deprecated types: HowTo (Sept 2023), SpecialAnnouncement (Jul 2025), Dataset (late 2025)
- Server-rendere
